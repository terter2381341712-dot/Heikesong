# 每台设备的自动环境准备

Windows 双击 `P4/start.cmd`，macOS 双击 `P4/start.command`。Linux 可执行 `bash P4/start.command`。首次联网下载并准备，完成后打开原工作台。无需手工安装或切换 Python、Node.js，也不修改系统 PATH、系统 Python 或已有 `.venv`。

所有设备走相同流程，包括已经能运行项目的开发者 Mac。启动器每次检查 `P4/var/runtime/` 中的专用环境；合格则复用，不合格则安装并再次核验，失败时停止启动，不借用全局环境。启动器、CPU、P2、可选 CUDA 的 Python 均固定为 **3.12.15**；目录仍分别管理这些环境以及工作台 Node.js 22。CPU/GPU 分发不混装。

已安装的 3.9.6/3.11.9 专用环境将因版本核验不通过而进入修复流程，不会被当作可用的 3.12.15 环境。更换版本前应退出所有旧启动器。CUDA profile 的 Python 要求随本次正式调整，其他冻结依赖、权重和模型摘要保持不变；两端须同步并重新配对。GPU 真实推理及全新机器安装仍需实机验证。版本统一不等于此前 micromamba 索引解析异常已经解决。

计算配置仍使用 `P4/var/compute.json` 或 `--compute-config`，不增加工作台设置页。CPU 默认配置不变；CUDA 选择 `heterogeneous` 和 `node.backend=cuda`，无需填写 `node.python`。该路径及 `P4_P1_PYTHON`、`P4_P2_PYTHON` 仅保留为开发维护覆盖选项。原模型锁文件、配对与 Token 载荷不改。

## 准备步骤与失败重试

1. 按系统架构下载固定版本的 micromamba，使用仓库内 SHA256 校验，通过后才执行；无需安装 Conda 或执行 shell 初始化。
2. 在应用目录准备启动器解释器，再准备工作台、CPU、任务环境；启用 CUDA 时准备 GPU 环境和私有 CUDA/cuDNN 库。不会自动安装显卡驱动或修改防火墙。
3. 核验解释器版本、依赖版本和真实模块导入，并在安装后执行依赖一致性检查。修复计算环境时先移除相反的 ORT 分发，再重新安装正确版本。
4. 所有必需环境核验完成后打开工作台。角色启动和重新连接还会再次检查对应环境；真实 GPU 模型会话继续使用原有 provider 校验，不允许静默回退 CPU。

阶段进度显示在启动窗口；详细依赖安装日志为 `P4/var/runtime/setup.log`。首次解释器下载的输出保留在终端。下载失败时重新启动可重试，已经通过检查的环境会复用。准备期间不要移动项目目录；移动后需重新准备环境。不要在任务运行中升级或修复正在使用的环境，更新前按原流程停止服务。

准备锁避免两个启动器同时安装。macOS/Linux 若安装器被强制结束而遗留 `.bootstrap-lock`，启动窗口会明确提示；确认启动器已关闭后移除该空锁目录再重试。Windows 使用随进程释放的文件锁。

仅准备、不打开工作台：macOS/Linux 使用 `bash P4/start.command --prepare-only`；Windows 终端使用 `P4\start.cmd --prepare-only`。这不是跳过准备的开关，而是用于部署验收的同一完整流程。

## 验收边界

G1 增加固定检查：每台参与设备分别验证首次准备、已有专用环境复用、缺失依赖后的修复、失败后重试；开发者电脑不能免验。记录专用解释器实际路径、版本、安装日志及启动结果。Windows 还须验证未预装 Python/Node.js 的设备、含空格的项目路径、DLL 加载及停止后重新启动。通过这些检查后继续原 G2–G7 链路，不用依赖安装成功代替双机 OCR 验收。

本轮已在 Apple Silicon Mac 从空的应用专用目录完成准备，并验证再次启动逐项检查后复用；专用 CPU 环境通过 P1 回归和真实 OCR 模型识别。Windows GPU 已完成依赖包解析检查，尚未完成 Windows 实机自动安装、驱动/DLL 加载、GPU 推理及双机浏览器验收，不据此宣称 S2 或最终产品发布通过。Intel Mac、Linux 同样需要对应实机验收。

环境准备不等于吞吐量验收。原计划的相同输入、人工质量参考、三轮测量、有效成功结果去重和双机贡献要求仍然保留；本次单张环境识别检查不用于性能结论。

下载来源：[micromamba 固定版本](https://github.com/mamba-org/micromamba-releases/releases/tag/2.3.3-0)、conda-forge、PyPI。GPU 库组合依据 [ONNX Runtime CUDA 兼容表](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html) 采用 CUDA 12.x/cuDNN 9.x；依赖可解析仍需实机验证。传递依赖目前由各组件现有版本约束解析，尚非所有平台的完整离线发行包。
