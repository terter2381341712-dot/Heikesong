# Windows / macOS / Linux：任意电脑分配角色

常用的“本机中心P1+P2、另一台P1计算”现在优先使用 [一键连接](一键连接.md)，不用编辑机器JSON或手动分发令牌。本文保留为高级任意分工部署说明。

电脑的操作系统不决定它运行P几。每台都有同版代码时，用本机配置选择要启动的角色；不要让程序根据操作系统猜角色。

## 先分清三个角色

| 名称 | 属于哪个模块 | 作用 | 数量 |
|---|---|---|---|
| resource | P1中心资源服务 | 保存文件、管理节点、接纳执行 | 同一集群1个 |
| task | P2任务服务 | 拆Job、准备与调度、汇总和下载 | 同一集群1个 |
| node | P1计算节点 | 主动注册到resource并执行OCR | 每台想提供算力的电脑1个 |

所以“这台运行P1”还需要明确是 resource、node，还是两者。三个角色可以任意组合；资源中心和P2可以在不同电脑，也可以同机。

例如，Windows电脑只运行node，Mac运行resource，Linux运行task+node；也可以完全反过来。这是部署配置支持的组合，不表示所有系统/架构的真实OCR都已验收。当前只有Windows候选补丁做过本轮真实单机OCR，macOS/Linux及混合物理多机仍待验证。

```text
node（任意多台） ──主动连接──→ resource（选定一台，默认8001）
                                      ↑
                          task（选定一台，默认8002）
                                      ↑
                                 Edge Fabric 工作台 / 验收客户端
```

**本轮角色在启动前选择。** 不自动选主、不自动迁移中心数据库。换电脑运行resource或task时，旧Job和身份数据不会因为修改配置就自动转移；不要在活动任务期间随意换中心，需另行停机备份和迁移。增加/关闭node则可按共享逻辑进行。

## 1. 每台安装自己要用的环境

源码可以复制，`.venv`、数据库、节点身份目录不要跨系统/电脑复制。启动器本身只用Python标准库，可用Python ≥3.9；它按本机系统自动选择组件解释器：

| 组件 | Windows默认 | macOS/Linux默认 |
|---|---|---|
| P1环境 | P1/.venv/Scripts/python.exe | P1/.venv/bin/python |
| P2环境 | P2/.venv/Scripts/python.exe | P2/.venv/bin/python |

需要P1的电脑按P1 README装环境，真实OCR的Python锁是**3.9.6**，以及RapidOCR3.10.0、ONNX Runtime1.19.2、Pillow11.3.0。不是任意Python3.9。ARM/x86、系统版本及依赖能否实际安装仍需在对应电脑核实；安装或模型核验不通过时保持不可用，不降低锁定标准。

Windows示例（确保py -3.9实际指向3.9.6，不是其他补丁版本）：

```powershell
py -3.9 -c "import platform; assert platform.python_version() == '3.9.6'"
py -3.9 -m venv P1/.venv
P1/.venv/Scripts/python.exe -m pip install -r P1/requirements.txt
```

macOS/Linux示例（用真正的3.9.6解释器路径替换 /path/to/python3.9）：

```sh
/path/to/python3.9 -c "import platform; assert platform.python_version() == '3.9.6'"
/path/to/python3.9 -m venv P1/.venv
P1/.venv/bin/python -m pip install -r P1/requirements.txt
```

需要 task 的电脑使用 Python ≥3.11，按 P2 README 用 `uv sync --project P2 --frozen --python 3.11` 创建独立环境。只有node不必装P2；只有task不必安装OCR依赖。非标准解释器位置可用 `--p1-python`、`--p2-python`，也可在本机JSON里填 `p1_python`、`p2_python`。

P1跨平台模型排序修复已纳入当前源码，见 [缺陷及回归记录](qa/issues/P1-Windows模型排序.md)。两端同步当前源码即可，不需要再应用历史patch；模型和锁文件保持原样。

## 2. 选两项地址，只生成一套集群凭证

先决定：

- R_IP：运行resource那台电脑的可达局域网IP。
- T_IP：运行task那台电脑的可达局域网IP，可以和R_IP相同。

Windows看 `ipconfig`；macOS看 `ifconfig`；Linux看 `ip -4 addr`。用真实联网网卡，不用127.0.0.1或监听地址0.0.0.0。FlClash、VMware等虚拟接口不自动代表其他物理电脑可达。

在任意一台管理电脑**只初始化一次**（替换示例IP）：

Windows：

```powershell
py -3 P4/scripts/cluster.py init --resource-url http://192.168.1.10:8001 --task-url http://192.168.1.20:8002
```

macOS/Linux：

```sh
python3 P4/scripts/cluster.py init --resource-url http://192.168.1.10:8001 --task-url http://192.168.1.20:8002
```

已有P4/var/config就复用；不要每台各init一套。向各台分发同一套生成文件中的相应配置：

| 本机roles | 本机config字段 | 从管理电脑复制什么 |
|---|---|---|
| node | P4/var/config/node.json | node.json，仅JOIN |
| task | P4/var/config/task.json | task.json，DEMO/TASK |
| resource（可含node/task） | P4/var/config/center.json | center.json，完整角色凭证 |
| task + node | P4/var/config/center.json | center.json，两个角色需要三种令牌 |

center.json在这里是集群配置文件名，**不代表使用它就自动启动中心**；实际运行什么只取决于roles。工具只向每个子进程注入该角色需要的令牌。含完整配置的机器应由可信人员管理。只复制所需配置文件，不复制整个var目录。

## 3. 每台编辑自己的 machine.json

把 `P4/config/machine.example.json` 复制为 `P4/var/machine.json`，每台单独改roles、config和node_name。文件可以在各系统上使用同样结构；这些路径相对项目根目录，与终端当前目录无关。所有启动命令仍建议从项目根执行。

仅作为计算节点：

```json
{
  "roles": ["node"],
  "config": "P4/var/config/node.json",
  "data_dir": "P4/var/this-machine",
  "node_name": "PC-01",
  "interactive": true
}
```

只运行P2：

```json
{
  "roles": ["task"],
  "config": "P4/var/config/task.json",
  "data_dir": "P4/var/this-machine"
}
```

既运行P2又提供计算，把roles改为 `["task", "node"]`，config改为 `P4/var/config/center.json`，并填写node_name。运行P1中心和本机计算用 `["resource", "node"]`；三者全运行用 `["resource", "task", "node"]`。

data_dir在每台电脑本地独立保留；重启沿用它。node_name建议用PC-01、Mac-02等ASCII名称，每台不同。`interactive: true` 表示节点最初不共享，启动后在终端输入on开启、off关闭；只影响node，不停止resource/task。需要启动后立即共享，设为false或省略。

可选设置：bind（默认0.0.0.0）、resource_port（默认8001）、task_port（默认8002）、p1_python、p2_python。修改端口时同步修改分发配置中的URL。JSON中不要填另一系统的解释器绝对路径；默认不填即可自动选本机路径。

## 4. 所有电脑用同一个启动入口

先检查配置和解释器路径，不启动服务、不暴露令牌：

```powershell
# Windows
py -3 P4/scripts/cluster.py run --machine P4/var/machine.json --plan
```

```sh
# macOS/Linux
python3 P4/scripts/cluster.py run --machine P4/var/machine.json --plan
```

--plan不验证网络、依赖版本或真实OCR，只检查启动配置及解释器文件是否存在。确认角色后去掉--plan正式启动。建议先启动resource，再启动task和各node。各电脑运行相同入口，roles不同即可。

不想写JSON，也可以直接任选组合。例如P2+本机计算：

```sh
python3 P4/scripts/cluster.py run --roles task node --config P4/var/config/center.json --data-dir P4/var/this-machine --node-name PC-03
```

Windows将开头python3换成py -3。其余参数相同；`--role center --with-node` 等旧命令继续兼容，但新部署建议明确列出roles。

## 5. 网络和验证

resource所在电脑开放受信任局域网TCP8001；task所在电脑开放TCP8002；node不需要入站监听。R和T在不同电脑时，开放端口也分别在那两台。其他节点与P2必须能访问R_IP:8001，客户端还必须能访问T_IP:8002。

Windows用 `Test-NetConnection R_IP -Port 8001`；macOS/Linux可用 `curl http://R_IP:8001/api/resource/v1/healthz`。将R_IP替换成实际地址。节点看到中心health正常仍不表示OCR就绪，需在资源快照中确认ONLINE/ACTIVE及profile核验，提交Job后等待自动准备。

完整上传/Job/结果/ZIP验收命令沿用 [P4 README](README.md) 第5节；验证机使用client.json，其两个URL分别指向R和T。同Job多物理设备证明和正式性能仍按原验收要求，不能用本机多进程替代。

高级分离部署中，按 [工作台 README](../web/README.md) 单独启动 Web，并配置资源服务与任务服务各自的地址。受信任的使用者在工作台连接设置中输入 DEMO_TOKEN。
