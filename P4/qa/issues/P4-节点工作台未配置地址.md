# 节点工作台报告 P1/P2 地址尚未配置

节点配对原先只保存中心 resource_url 和 JOIN_TOKEN；工作台的 bridge-upstreams 又仅允许 center 模式，因此节点本机的 5173 页面无法得到任何上游地址。即便填写了正确 DEMO_TOKEN，仍会出现两端地址未配置、设备列表不可用及无法上传。

修复：中心配对响应增加 task_url，节点校验并保存该地址；节点模式允许本机工作台获取远端资源/任务地址，且 lan=false，不向节点的局域网访问者开放转发。原有 JOIN-only 凭证隔离保持，上传仍需在设置中应用中心分配的 DEMO_TOKEN。节点工作台展示上传入口，直接进入上传流程，不调用仅中心可用的工作台令牌接口。旧记录提示更新中心后重新配对。

检查：P4 工具74 PASS / 1 SKIP，详见 ../node-workbench-pytest.xml。新增真实 Node Web 服务和真实 HTTP 测试中心，验证节点桥接、健康检查、设备查询、原始 multipart 字节转发、任务创建转发，以及无用户令牌返回401；不启动本机 P2。测试中心为受控接口桩，本轮没有重新执行物理双机 OCR。既有控制台 JavaScript 三项通过，设备控制脚本语法、Ruff 通过。

部署：两端更新并退出旧控制台后重启，节点重新粘贴中心新连接码，然后在设置应用中心 DEMO_TOKEN。旧配对不会自动补齐 task_url。
