# 节点入口在 Windows 嵌入式 Python 下导入失败

现场现象：本机角色为计算节点，但 Web 工作台提示“服务已退出”“本机计算节点未启动”。node.log 最后两次启动均报 `ModuleNotFoundError: No module named 'control'`，位置为 managed_node.py 导入 save。资源服务的旧心跳日志不能证明当前本机计算节点在线。

原因：主线心跳状态快照功能新增了 `from control import save`。Windows 嵌入式 Python 的路径隔离会忽略脚本所在目录，因此该导入发生在补充 P4/scripts 路径之前时会失败。

修复：节点入口先显式加入 P4/scripts，再导入 control；本机节点退出后可通过开启计算重新启动；节点模式的退出提示明确指向本机计算日志；工作台日志标题补充设备名并区分历史服务日志。P1/P2 产品源码及解释器版本要求未修改。

检查：Python 3.9.6 执行 `-I P4/scripts/managed_node.py --help` 成功；回归包含从其他工作目录启动隔离解释器及退出节点重试。P4 工具 72 PASS / 1 SKIP，证据为 ../node-isolation-fix-pytest.xml；既有控制台 JavaScript 测试3项通过；工作台设备控制脚本语法检查与 Ruff 通过。本轮尚未重新确认现场跨机注册及 OCR。

更新后需在原启动终端 Ctrl+C 退出，再运行 P4/start.cmd。P1 节点设备使用已配对中心重连，或者重新粘贴中心连接码；无须在节点设备启动中心或 P2。是否成功以新的本机计算日志、中心设备列表和心跳确认为准。
