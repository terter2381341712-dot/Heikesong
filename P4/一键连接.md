# 两台电脑用按钮连接

## 推荐：只粘贴一个连接码

两台同步最新 P4，退出旧启动终端后重新启动。中心点击“启动中心 P1 + P2”，再点击“复制连接码”；另一台在“连接码”输入框粘贴，点击“连接并开启计算”。无需查找中心、填写地址或复制配置文件。剪贴板不可用时，页面会选中连接码，用 Ctrl+C（Mac 用 Command+C）复制。

连接码以 `P4-1-` 开头，内含中心 IPv4、控制台端口及临时六位配对凭证，并包含校验信息以识别复制错误；它不是加密内容，也不包含 JOIN/DEMO/TASK 长期令牌。有效期 10 分钟，由中心校验；刷新连接码后旧凭证失效。只发送给允许加入的设备。地址变化时需重新启动中心并复制新码，两台网络仍需互通。二维码本轮未实现。

旧的地址加六位配对码入口收起在“兼容旧版”中；以下旧版流程留作排查参考。

控制台操作更新：中心运行后，勾选或取消“本机也提供计算”会开启或暂停本机计算，也可使用下方同名按钮。“停止本机服务”关闭本页启动的计算节点及中心服务，保留数据。操作期间显示阶段与耗时；环境安装或图片测试期间需等待当前操作结束，重复点击不会启动第二个操作。停止子进程和图片验证均有等待上限，失败会显示错误供重试。

日志标题标注本机设备名与服务用途；节点计算日志记录设备名、执行编号、输入标识，中心图片测试完成后记录各执行的贡献设备与结果。中心不会拉取远端电脑的完整原始日志，远端详细日志在对应电脑查看。日志更新保留阅读位置；在底部阅读时跟随更新。

本轮检查：Python 3.9.6 回归 61 PASS / 1 SKIP；`node --test P4/tests/control_ui.test.cjs` 两项通过；Ruff 通过。更新生效需先同步代码，再在旧启动终端 Ctrl+C 退出后重新启动：Windows 使用 `P4/start.cmd`，Mac/Linux 使用 `bash P4/start.command`。仅刷新网页不会替换后台代码，当前连接也不会被本轮文件修改主动断开。

多网卡发现已修复：中心会公布实际使用的局域网地址，各网卡分别发起查找，加入列表不再显示本机中心。配对码旁会显示中心地址；未自动发现时，在另一台电脑展开“未发现中心？手动输入地址”，填写这里显示的 `IP:端口` 并输入当前配对码即可，无需复制配置。现场 Mac 手动连接 `10.4.142.66:8003` 已由用户确认成功；自动发现修复需两端同步后重启控制台复验。详见[多网卡发现记录](qa/issues/P4-多网卡发现.md)。

Mac虚拟环境路径修复：启动器已保留P1/.venv/bin/python入口，不再resolve到系统Python。请同步包含本修复的最新P4代码，退出旧控制台后重新启动；程序会在选中的同一个3.9.6虚拟环境补齐P2依赖，不必重装Python或卸载系统中已有的P2包。具体原因和回归见 [路径缺陷记录](qa/issues/P4-Mac虚拟环境路径.md)。

现在日常操作使用本地控制页面，之前的命令行部署保留给排查和高级分工，不需要再手动复制node.json、令牌或填写解释器路径。

## 1. 两台同步本次最新代码

包括新的P4入口和P1模型排序修复。可以复制同一份源码；本机环境由程序检测。运行数据只在本机保存；控制台会识别常见的跨电脑复制身份情况，重新生成本机标识，配对记录也绑定本机，避免照搬另一台的节点身份。

## 2. 打开控制台

- Windows：双击 **P4/start.cmd**。
- Mac/Linux：在项目根目录的终端执行 **`bash P4/start.command`**。这是打开页面的入口，之后在页面操作。如果文件已带执行权限，Mac也可直接打开start.command。

会自动打开本机浏览器 `http://127.0.0.1:8003`。若浏览器没有自动弹出，手动打开这个地址。启动控制台的终端保持运行；Ctrl+C退出控制台并停止它启动的服务。页面仅供本机访问，远端设备只访问配对接口和P1/P2服务。

## 3. 你这台点“启动中心 P1 + P2”

默认勾选“本机也提供计算”，可取消。程序自动选局域网网卡、检测P1/P2解释器和依赖、创建独立数据目录、启动服务并生成一个六位配对码。已有依赖直接复用，缺依赖且有对应解释器时会自动建环境、下载依赖，首次可能需要几分钟。

一个集群只选一台启动中心。系统不决定角色：Mac、Windows或Linux都可以选择此按钮，但对应环境必须通过检测。

## 4. Mac 输入配对码，点“连接中心并开启共享”

页面自动查找中心；如果Mac页面先打开、中心后来才启动，点击连接时会再查找。中心不止一个时，在列表选择正确的中心。配对会核对协议、P1源码和模型锁版本，只把JOIN角色凭证写入Mac本机，不复制中心的DEMO/TASK令牌。

以后重启页面，点“重新连接已配对中心”即可，不必重复输入码。若中心IP改变、源码/模型锁更新、换了中心或复制到了另一台电脑，则重新配对。中心码10分钟有效，连续5次错误后需在中心点“刷新配对码”。

Windows与Mac的Git换行设置可能不同。按钮入口自动生成统一LF的运行profile副本，模型字段和版本要求完全不变，两端自动使用一致字节；原始文件不改。原始SHA与运行SHA记录在本机 `P4/var/control/profiles/manifest.json`，不需要手动复制锁文件。手工CLI和按钮路径的profile摘要可能不同，正式测量不能混用。

## 5. 测试与开关

- 中心点 **“测试两张图片”**：自动生成两张测试图，上传、创建Job、等待真实OCR、检查输入/执行/结果关系及ZIP；成功后点 **“下载最近测试结果 ZIP”**。
- Mac点 **“关闭本机共享”** / **“开启本机共享”**：通过本机控制通道调用P1已有共享逻辑，无需在终端输入on/off。按钮表示发出请求，最终状态看中心设备列表和节点日志，不能把点击当作停止确认。
- 点 **“停止本机角色”**：停止本次启动的服务，数据保留。单纯关闭浏览器页面不停止服务。关闭节点共享不会关闭中心P1/P2。

测试两张图证明计算和接口闭环，未必能让两台都分到任务，不代表正式两机协同或压测通过。正式同Job两机贡献和物理设备映射仍按P4验收步骤执行。

## 首次环境和网络的实际限制

打开控制台需要Python ≥3.9。现在中心与计算节点均可统一 **Python3.9.6 / RapidOCR3.10.0 / ONNX Runtime1.19.2 / Pillow11.3.0**。按钮入口找到P1的3.9.6后，会在同一环境补齐P2依赖并共用该解释器，不再要求另装3.11；只跑Mac计算节点时不安装P2依赖。程序自动寻找解释器、准备依赖；**不会自动安装操作系统级Python或编译器**。缺解释器时安装一次3.9.6即可，无需手改路径。安装失败不会回退为模拟OCR。

从此前双版本入口更新时，请先在旧控制台终端按Ctrl+C退出，再重新打开。只刷新浏览器或关闭网页不会替换后台已经加载的环境检测逻辑。

同样的源码不等于各系统的Python/模型运行环境都已可用；Mac实机及混合系统两机测试仍需实际执行。本轮Windows的环境检测、发现、配对、共享确认和真实OCR已测，见验收报告。

正常同一可信局域网可以自动发现；如果网络隔离或防火墙阻断，程序不能绕过。首次系统询问Python网络权限时允许受信任私有网络。中心使用TCP8001、8002、8003和UDP37043。自动发现失败时展开“未发现中心”输入中心局域网地址即可，不需要复制配置；若IP也无法访问，需先解决网络互通。

高级的P2分离部署仍可用 `cluster.py --machine`，不是这个简化页面的默认流程。独立Mac节点不需要安装P2。
