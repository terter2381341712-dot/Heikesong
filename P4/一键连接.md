# P4 一键连接

计算节点也可在本机工作台上传图片。中心与节点更新后重新配对一次，新记录会保存远端 P1/P2 地址。在节点工作台设置中应用中心提供的 DEMO_TOKEN 后，即可查看设备、上传图片和提交任务；无需启动本机 P2 或另一个中心。旧配对记录缺少任务地址时必须重新配对，仅修改令牌不能补齐地址。

## 启动控制台

所有电脑同步同一份代码。Windows 双击 `P4/start.cmd`。macOS 或 Linux 在项目根目录执行 `bash P4/start.command`。默认打开 Edge Fabric 前端 `http://127.0.0.1:5173/`，在 **设备资源 → 本机控制** 操作。已经运行时，启动脚本会打开该实例实际使用的前端地址。前端启动需 Node.js 22 或以上。

只运行计算节点且未安装 Node.js 时，可显式运行 `P4\start.cmd --control-only`（Windows）或 `bash P4/start.command --control-only`（macOS/Linux），打开本机 P4 控制台。

| 角色 | 需要安装 |
| --- | --- |
| 中心和工作台 | Python 3.9.6（P1）、Python 3.11 或以上（P2）、Node.js 22 或以上（Web） |
| 计算节点 | Python 3.9.6（P1） |
| 只打开控制台 | Python 3.9 或以上 |

启动时会优先检测对应组件的 `.venv`，也可以通过 `P4_P1_PYTHON`、`P4_P2_PYTHON` 指向已有解释器。缺依赖时会创建独立运行环境并安装。P1 仍使用现有 OCR 模型锁和依赖版本。

## 打开真实工作台

1. 在中心电脑的工作台打开 **设备资源 → 本机控制**，点 **启动中心**。默认同时启动本机计算。要邀请其他电脑，选择它们能访问的 Wi-Fi 或网线地址。单机测试可选 `127.0.0.1`。
2. 在 **设备资源 → 本机控制 → 真实工作台**，点 **连接此工作台** 给当前页面授权。要让其他电脑上传图片，点 **复制工作台令牌**，把令牌和卡片内的局域网工作台地址交给获准使用的人。对方在该工作台的 **设置 → 用户令牌** 中粘贴。
3. 控制台的 **测试两张图片** 会调用 P4 验证器生成并上传测试图，执行真实 OCR，校验结果关系和 ZIP。工作台的 **本机控制 → 查看测试进度** 可跟踪同一 Job 的逐文件状态，完成后点 **查看测试结果** 或 **下载测试 ZIP**。日常识别可在同一面板点 **上传图片**，提交自己的 JPG、PNG。

控制台默认使用 TCP 8003，中心 P1/P2 分别使用 TCP 8001/8002，工作台使用 TCP 5173。已运行的服务占用端口时，可先停止对应服务。仅工作台端口冲突时，可从项目根目录执行 `python P4/scripts/control.py --web-port 5174` 改用其他空闲端口。

## 上传自己的图片测试

中心启动后，在 **设备资源 → 本机控制 → OCR 测试** 展开 **测试自选图片**，选择 PNG/JPG（最多 20 张，总计 20 MB），再点 **上传并测试**。该批次使用所选图片。“测试两张图片”使用内置示例。格式不正确、内容重复或超出限制会提示错误。

成功结果标题按北京时间显示到秒，例如“测试结果 · 2026-11-14 22:35:08（北京时间）”。保存目录及下载 ZIP 名称带 `test-20261114-223508-随机标识`，同秒测试也不覆盖；目录内 `test-info.json` 记录开始时间、输入来源及文件名。上传原图保留在该次目录的 inputs 中，不会随 Git 上传。单次仍等待最多180秒的真实 OCR 验证；图片较多或较大可能超时，失败证据保留在该次目录。

## 接入另一台电脑

1. 中心选可信局域网地址启动，点 **复制连接码**。
2. 另一台打开自己的控制台，粘贴完整连接码并点 **连接并开启计算**。也可展开 **使用地址和六位配对码**。允许中心的 TCP 8001、8003，自动发现另需 UDP 37043。
3. 配对码有效期 10 分钟，连续错 5 次后可由中心刷新。配对仅颁发节点加入凭证，会核对 P1 源码和模型锁。节点发起注册后，本机控制以中心心跳确认显示在线和算力状态。节点可重连已配对中心，中心地址变更后重新配对。
4. 用 **开启这台电脑的计算** 或 **暂停这台电脑的计算** 控制共享。以中心设备列表和节点日志确认状态。**停止本机服务**会停止本机计算和后端，当前工作台页面保留并显示断开，可在页面重新启动。关闭浏览器页面后服务继续运行。结束整个启动器时可在终端按 Ctrl+C，此操作同时关闭它托管的工作台。

## 三台电脑现场联调

1. 让 A、B、C 接入同一个允许设备互访的局域网。A 安装中心和工作台依赖，B、C 安装节点依赖。三台各自运行一份源码，保留各自的本机身份和数据目录。
2. A 打开本机工作台，进入 **设备资源 → 本机控制**，选与 B、C 同网段的 Wi-Fi 或网线地址，保留 **同时共享本机算力**，启动中心。把同一个有效连接码复制给 B、C。
3. B 和 C 分别打开各自的 P4 页面，只选择 **加入中心**。粘贴连接码，等待本机页面收到注册确认。A 的 **设备列表** 应出现三个不同的设备，状态为在线且可接单。自动发现受限时仍可直接粘贴连接码。连接码失败时，在 B、C 检查 A 的 TCP 8003（配对）和 8001（节点注册）是否可达。
4. A 先点 **测试两张图片** 验证基本链路。然后在工作台上传一批约 20–30 张内容不同的 JPG 或 PNG。打开 **任务进度**，逐文件查看执行设备和分派记录。完成后打开 **识别结果**，核对原图、文本并下载 ZIP。
5. 三机协同验收以同一个 Job 中 A、B、C 各有至少一条成功结果为准。截图记录 Job ID、执行设备和完成状态。如果有节点未分到任务，先检查该节点的 OCR 就绪状态、可用槽位，再用新的一批图片复试。调度按可用槽位和准备状态分派。
6. 验证断线恢复时，先在 B 或 C 暂停计算，A 确认另两台仍可接任务，再恢复该节点。最后在 A 停止本机服务，确认工作台保留、显示断开，并能从同一页面重新启动。

两张测试图用于验证链路。正式双机验收要求同一个 Job 的有效结果来自两台独立物理设备，证据要求见 [P4 正式验收](README.md)。
