## 结果持久化与恢复证据

- 完整分派请求在 HTTP 发送之前写入 SQLite，未知接纳不伪造 ACCEPTED 摘要。
- 只有确定接受才增加尝试次数；重复查询与重放不重复计数。
- 结果 JSON 与 Task 成功在同一事务提交；模拟中断发生在提交前时，恢复后重新取原结果。
- 成功执行的结果文件暂不可下载，不再申请推理；其他可运行输入继续处理。
- 取消标记在独立更新中保存，网络响应回来后不会覆盖并发取消。
- 进程级测试停止 P1，再重启 P2，已完成 Job 的结果和 ZIP 可继续读取。
- 数据目录独占锁阻止同时启动两个调度器。

## 证据边界与待接入项

模拟 P1 使用明确标注的合成节点、预置 PNG 和 `MOCK OCR` 文本，通过查询推进执行。进程级测试证明的是 P2 HTTP、后台调度及持久化路径，不证明物理多机或 OCR 效果。

## 复现

从仓库根目录运行：

```sh
uv sync --frozen
uv run --frozen pytest -q --junitxml=docs/p2-pytest.xml
uv run --frozen ruff check task_service splitters aggregators tests/tasks
uv run --frozen ruff format --check task_service splitters aggregators tests/tasks
git diff --check
```

测试会自行管理临时端口、数据目录和子进程，不使用正式 P1 数据，也不在测试结束后保留服务进程。
