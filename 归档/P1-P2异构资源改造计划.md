# P1/P2 异构资源改造计划

日期：2026-11-14。当前实施范围为第一阶段：NVIDIA CUDA 接入、CPU/CUDA 模型常驻、保留取消与共享退出接续。多槽、资源预算调度和 GPU 合批是后续工作，不能将接口预留当作已经实现。

## 阶段一：CUDA 与常驻模型（已实现，本机验证与 Windows 验收分开）

### P1

- 保留 `ocr.default.v1` 原 CPU 锁文件及默认目录；新增可选目录 `P1/profiles/heterogeneous/`，发布 `ocr.heterogeneous.v1`。同一 profile/digest 固定相同模型、预后处理，允许 CPU/CUDA 两个依赖变体。已有 Job 不自动切换 profile。切换中心目录前先排空旧 Job，或为新目录启动独立中心数据目录。
- `load_locked_runner()` 按 backend 校验运行环境。CPU 使用 Python 3.9.6、onnxruntime 1.19.2；CUDA 使用 Python 3.11.9、onnxruntime-gpu 1.19.2。RapidOCR 3.10.0、Pillow 11.3.0、三组模型 SHA 一致。禁止同一环境同时安装 CPU/GPU 两种 ORT 分发包。
- Agent 新增 `--backend cpu|cuda`、`--device-id`、`--threads`。第一阶段显式选择后端，不根据操作系统猜测，也不自动降级。CPU 与 CUDA 节点均能执行同一新 profile。
- 硬件注册使用实际 CPU 核心数、内存；NVIDIA 探测和心跳采样绑定所选 device-id。硬件存在不等于能力 READY：实际会话加载、provider/device 核验、三图 OCR 自测全部通过后才能上报。
- CUDA 为三个 ONNX 会话显式配置 CUDA；允许未支持算子的 CPU 图分区，但禁止执行失败后整会话静默切换 CPU。中心同时验证锁文件允许的 backend/provider、模型 SHA、自测。真实算子落点由 Windows `gpu_probe` 留证，不把 provider 名称当成全部算子在 GPU 的证明。
- 一个节点仍是一槽。准备与连续任务由同一常驻子进程执行；正常完成保留模型，取消/共享关闭/失联/会话失效/硬截止终止并 join 子进程。停止确认原子撤销会话与 READY；重新注册、自测后再接单。
- 常驻进程异常退出按同样流程撤销会话，活动执行确定失败后可按原三次预算重试；已有成功结果不变。SIGINT/SIGTERM 也停止进程并撤销会话。进程被 OS 强杀或整个设备断线时仍依赖租约和离线检测。

### P2

- 保持一图一 Task、同 Job 固定 profile、原 ID 对账、最多三次已接受尝试、顺序汇总与持久结果。
- 既有 `candidate_action()` 已接纳经过核验的 CPU/CUDA 能力；无需为 GPU 复制 Job 或另写业务调度器。本阶段仍按节点轮询，不宣称已经实现 GPU 优先/显存感知调度。
- 新增 CPU/CUDA 混合节点协议测试，以及 GPU 节点关闭共享后同 profile 接续到 CPU 的测试；保留普通 Job 取消不迁移的现有行为。

### 接口和兼容性

| 接口/文件 | 调整与约束 |
|---|---|
| RuntimeProfile | 新增可选 `backend_dependencies`，按 cpu/cuda 映射到精确依赖版本；旧 profile 缺失时仍使用 dependencies。三份 OpenAPI 同步，公开 HTTP 数据格式保持 0.2.0 |
| Preparation READY / ResourceNode.capabilities | 复用既有 backend/runtime_provider/model_sha256/calibration 字段；中心不再写死 CPU，必须匹配冻结 profile |
| `POST /api/resource/internal/v1/nodes/{worker_id}/runtime_stopped` | 新内部接口；body 为 session_id/node_secret，表示 Agent 已确认所有模型子进程退出。事务内完成待取消工作/失败其他活动工作，撤销 READY、轮换会话并离线，返回 `{ok:true}`。旧会话重放 409 SESSION_CHANGED，恢复只能重新注册 |
| cancel_ack | 旧内部接口保留；新 Agent 使用 runtime_stopped 在同一事务确认停止并撤销运行时，避免先释放槽位、后撤销 READY 的竞态 |
| 共享关闭与取消 | 关闭共享的 CANCELLED 保留 NODE_UNAVAILABLE、retryable=true、原 execution_id；P2 继续按原规则迁移。普通 Job 取消不重新排队。成功提交与停止确认按中心事务顺序仲裁 |
| 日志 | `model_loaded pid/backend/device_id/provider/load_ms` 与逐 execution 的 PID/后端记录，用于核对常驻和设备选择；不包含令牌 |

新 Agent 必须配套更新后的 P1 中心；旧中心不认识 runtime_stopped。P2 无需迁移数据库。CUDA profile 的可用声明仍由实机准备结果决定，仓库内锁文件不代表 Windows 已验证。

## 阶段二：CPU 多槽与线程预算（本次已实施）

按本轮范围实现 CPU 每槽一个常驻模型进程、显式线程预算、P1 原子占槽与代次隔离、心跳按存活执行续租，以及 P2 按剩余槽位派单。GPU 继续单卡单槽；普通取消只重建一个槽，整机共享关闭停止全部槽并沿用任务迁移标记。公开契约升级为 0.3.0，旧客户端必须同步升级。

具体配置、接口、数据库迁移与限制见 [多槽使用说明](P1/docs/CPU多槽与线程预算.md)，本机测试与真实 OCR 证据见 [第二阶段报告](qa/p1-p2/CPU多槽实施报告.md)。

后续仍待实施：同节点多 backend/resource_pools、每卡独立配额、内存/显存预算准入，以及代表性数据上的 CPU 1/2/4 槽吞吐对照。本轮线程预算是计算库并行度配置，并非操作系统硬配额。

## 阶段三：资源感知调度（已实施）

在 `zyc` 分支完成 P2 调度改造：先检查实际 CPU/CUDA provider、冻结 profile、线程预算和剩余槽位，再按已验证成功执行的下载、推理与其他开销估计耗时。历史按节点、后端、模型、槽/线程配置和图片像素桶隔离；无有效历史回退自测，并定期探索和预热冷节点。GPU 不使用固定性能倍数，忙 GPU 不阻塞空闲 CPU。

决策与原请求同时持久化，成功样本与结果在同一事务提交，重启和重复对账不重复学习。独立对账/结果下载有并发上限和超时；不确定节点暂不接新任务，健康节点继续服务。取消、共享关闭和任务迁移沿用原状态语义。公开契约继续为 0.3.0。

配置、估计公式、内部数据表和限制见 [资源感知调度说明](P2/docs/资源感知调度.md)，本机真实证据见 [第三阶段实施报告](qa/p1-p2/资源感知调度实施报告.md)。

后续仍待验证/实施：Windows NVIDIA 与 Mac CPU 的物理多机性能对照、对比轮询的整批耗时/P95、跨 Job 公平配额、内存/显存动态准入，以及完全无阻塞的调度流水线。本阶段不将单机双 Agent 验证称为物理多机或 GPU 性能验收。

## 阶段四：GPU 输入流水线（已实施，本机验证；Windows GPU 待验）

在 `zyc` 实现一个未来输入的有界预取、独立 CPU 解码进程与当前推理重叠；GPU 保持单槽。提示不创建 execution 或占槽，带会话、修订号和 15 秒 TTL。取消/共享关闭时先停止相关进程，再沿用停止确认与迁移语义。公开契约升级为 0.4.0，P1/P2/Agent 同步升级。

配置、接口和 Windows 验收清单见 [输入流水线说明](P1/docs/GPU输入预取与解码流水线.md)，本机真实 OCR 证据见 [第四阶段报告](qa/p1-p2/GPU输入流水线实施报告.md)。当前范围到输入下载/解码重叠为止；文本裁剪合批、跨图片微批、多卡池、动态内存/显存准入属于后续可选工作，不作为本轮完成条件。

所有阶段用相同真实数据、模型及质量门槛，区分冷启动/预热；报告正确结果吞吐、总耗时、P95、资源峰值、失败/重复计算成本和单机/多机效率。中心 HTTP/SQLite 暂保留，只有测出瓶颈后再改存储或高可用架构。
