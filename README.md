# Heikesong · 多设备 OCR 项目

**多电脑连接与 P4 验收入口：[P4/README.md](P4/README.md)。** 你的电脑运行中心 P1、P2 和本机节点；其他电脑仅运行 P1 节点，全部连接同一个中心。P4 提供 Windows/macOS/Linux 启动参数、角色配置、接口/字节/幂等/结果/ZIP 验证、设备映射、质量工具及演示步骤。当前实际执行范围见 [P4 验收报告](P4/qa/验收报告.md)，两台物理机与正式压测按现场证据签收。

电脑系统、分工不固定时使用 [任意角色部署说明](P4/多系统与任意角色部署.md)：每台设置自己的 machine.json，可组合选择P1中心(resource)、P1计算(node)、P2(task)。上面的固定中心方案仅为示例，不要求用户这台电脑始终运行中心。

P2 的代码、依赖、测试、开发文档及本地演示数据已集中放在 **[P2](P2/README.md)** 目录。队友 `wzq@7368ad0` 的 P1 原始实现已接入 **[P1](P1/README.md)**，两端保持独立环境。公共执行包与 P1–P4 的任务说明保留在项目根目录。

进入 P2 开发目录：

```sh
cd P2
uv sync --frozen
uv run --frozen pytest -q
```

服务启动与配置见 [P2 使用说明](P2/README.md)，真实接入要求见 [P1 联调清单](P2/docs/P1-联调交接清单.md)。

两端环境按各自 README 安装后，从项目根目录执行 `P2/.venv/bin/python qa/p1-p2/run_local.py check` 可复验真实闭环；改用 `serve` 可明确启动本机 P1（8001）、P2（8002）与节点。已通过的范围与尚缺的物理两机验收见 [实际联调报告](qa/p1-p2/实际联调报告.md)。

用户确认的“手动选择中心、开启共享、关闭后立即停止本机工作并迁移剩余图片”另见 [共享开关与任务迁移补充计划](P1-P2设备共享开关与任务迁移补充计划.md)。该新增行为尚未实现，不能用现有基础联调通过替代验收。
