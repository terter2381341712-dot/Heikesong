# P2：Worker、硬件识别与本地模型

你的职责是让同一条图片流水线在三台设备上真实运行，并让设备可以安全接入和退出。你是模型、依赖与运行后端的唯一负责人。

## 给 AI 的任务说明

> 实现 D 题“弹性商品图工坊”的跨平台 Python Worker。先读取 `contracts/openapi.yaml`、架构文档和流水线清单模板。只编辑 `worker/`、`tests/worker/`，并向 P1 提供流水线 manifest 的更新内容。优先在 Mac CPU 跑通明确选择的本地 u2net 模型，然后接 Windows CPU/CUDA；不能使用外部推理 API。自动检测配置，校准通过后注册为可执行，采用单任务槽位、独立心跳、带租约领取、结果幂等提交。模型会话必须复用。完成真实单图能力后立刻和 P1 对接，不等所有优化完成。

## 需要实现

- `python -m worker` 命令；server/name/backend 参数；JOIN_TOKEN 读环境。
- installation_id 持久化、instance_id 每次启动更新；注册失败有限退避，日志不打印令牌。
- OS/CPU/内存探测；可用 provider、实际加载后的 provider 与降级原因；NVIDIA 信息尽力采集，未知写 null。
- 人工填写显示名称和备注；不让手工字段伪造 CUDA 能力。
- 固定 3 张校准图片、自测输出和耗时；WARMING/READY/ERROR；记录模型 SHA256。
- 独立心跳循环和资源采样；领取请求幂等；网络错误先 heartbeat 对账再领取。
- 规范化输入下载、真实抠图、固定三种输出、multipart 提交和稳定 submission_id；保留当前输出供网络重试。
- DRAINING 停止领取并完成当前任务；SIGINT 走优雅退出；强制终止由服务器租约回收。
- 被撤销任务丢弃输出；不可恢复的本机模型错误进入 ERROR；不无限快速重试。

## 第一小时优先做

先让两台 Mac 在本地各处理一张新照片；确认运行后端和输出质量。随后在 Windows 验证。模型和启动环境失败就立刻记录，不花半天“顺便升级一整套 CUDA”。先保留 CPU 路径。

## 三台机器的计划

| 设备 | P0 | 可选增强 |
|---|---|---|
| M4 16GB | CPU、1 槽位，协调服务另进程运行 | 有余量再调线程，正式测试前冻结 |
| M1 Max 64GB | CPU、1 槽位，不用 64GB 推导显存或任务份额 | CoreML 等后端只在全部 P0 稳定后考虑 |
| Windows 4050 | CPU 路径必须可用；CUDA 自测成功后切换 | 报告真实 GPU 利用率和显存 |

## 对接和交付

- 给 P1：pipeline_id、权重 hash、所需输入、输出格式、校准结果、版本锁定文件。
- 给 P3：通过服务器传递配置和阶段，不另建直连 Worker 的 API。
- 给 P4：三台的安装/启动命令、模型缓存位置、实际后端、逐任务日志、来源和许可清单。
- 模型权重和依赖提前准备；首次下载时间与动态加入时间分别记录。

必须通过 A01/A02/A03/A04/A05/A07/A14，配合 A06/A11/A12/A20。完成标准是一位队友照说明启动后加入队列、真实产生结果、能退出恢复，而非只完成本机模型脚本。
