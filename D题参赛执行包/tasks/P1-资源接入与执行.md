# P1：资源接入与执行平台

版本：0.2.0。本文是待实现任务，不代表设备已接通或模型已验证。

## 1. 交付边界

让授权电脑接入同一资源平台，真实报告“有什么、能做什么、现在能否接单”，并执行 P2 已经拆好的子任务。P1 包含资源服务、各电脑上的节点程序、模型准备和执行器。

| 你负责 | 不属于你的职责 |
|---|---|
| 局域网/热点互通、注册、心跳、会话、退出 | 用户 Job 的创建、拆分和合并 |
| 硬件探测、后端自测、能力目录、占用管理 | 为整批 Job 决定子任务和节点的对应关系 |
| 固定配置的模型下载、校验、缓存、加载 | 失败后是否换节点、增加一次业务尝试 |
| 原子接单、单次执行、撤销、拒收旧结果 | Job 进度、最终结果排序及 ZIP |
| 文件传输、执行日志、资源采样 | 前端页面、正式性能与产品报告 |

计划代码归属：`resource_service/`、`node_agent/`、`runners/`、`profiles/`、`tests/resource/`。这些是未来实现目录，本执行包未包含应用代码。

## 3. 对外接口

RESOURCE_BASE_URL 默认建议端口 8001；下表路径共同前缀为 `/api/resource/v1`。

| 接口 | 调用者 | 保证 |
|---|---|---|
| `GET /healthz` | 所有人 | service=p1_resource、contract_version=0.2.0；无鉴权 |
| `GET /resources` | P2/P3/P4 | 节点、会话、模式、槽位、能力与采样，未知值 null |
| `GET /task-types` | P2/P4 | 类型、限制、配置状态、不可变 profile 标识与摘要 |
| `POST /artifacts` | P2/P3/P4 | 原字节保存、SHA 可核验、上传幂等 |
| `GET /artifacts/{id}`、`GET /artifacts/{id}/content` | P2/P3/P4 | 元信息、实际文件跨电脑可取 |
| `POST /preparations`、`GET /preparations/{id}` | P2/P4 | 异步准备模型；真实自测后才 READY |
| `POST /executions`、`GET /executions/{id}` | P2/P4 | P2 指定节点；原子占槽；唯一执行记录 |
| `POST /executions/{id}/cancel` | P2/P4 | 撤销提交权；未停下的本机计算不能与新任务重叠 |
| `POST /resources/{id}/mode` | P3/P4 | DRAINING 做完当前工作后暂停；ACTIVE 恢复 |
| `GET /events` | P4 | 按 event_id 游标导出持久事件，不泄露凭证 |

令牌、字段和响应码见 OpenAPI。节点内部协议由 P1 一人维护；P2/P3 不需要实现它，也不直接访问节点端口。

## 4. 接单、故障与资源边界

1. execution_id 由 P2 先生成并落库。同 ID、同语义载荷重发只返回同一记录；不同载荷返回 409 IDEMPOTENCY_CONFLICT。
2. 通过鉴权及 schema 校验后，P1 将请求指纹及“接受或业务拒绝”原子落库。忙碌等拒绝也保存 REJECTED 记录；同一被拒 ID 不会稍后变成接受。
3. 接单时重新检查 worker_session_id、在线/ACTIVE、能力 READY、profile 摘要与空槽。资源快照不是预留。首版一节点一槽，准备模型也占槽。
4. 新接受返回 201；已接受记录重放返回 200；业务拒绝返回 409 并给出可查询的 execution_id。REJECTED 不消耗 P2 的执行尝试预算。
5. P1 只管理一次 execution。掉线、超时、失败后上报终态，**不自行向其他节点重派**。
6. 终态不复活；旧会话、撤销和过期执行的晚到结果不发布、不计数。相同成功提交可重放，内容变化须拒绝。

心跳 3 秒、失联阈值 15 秒、扫描不超过 1 秒，前端轮询 2 秒，离线显示目标为最后有效心跳后 18 秒内；不是重算时限。硬期限与取消确认详见接口手册。

## 5. 模型与执行器

首批计划类型为 ocr.image.v1、asr.file.v1，具体模型待你实测选定。每种类型须有解码、模型调用及规范输出执行器，下载权重不等于已具备能力。

P2 指定类型/profile，P1 按已发布配置准备环境，不接收任意模型 URL 或代码。每个 execution 输出一份子任务 JSON，P2 负责汇总。

首版每节点只保证一个驻留 profile；空闲时切换可将旧能力降为 NOT_PREPARED，缓存可保留。忙碌时不换模型。记录实际 provider 和降级原因。

## 6. 独立自测与连接交付

- 不等 P2：用契约执行请求验证自己的服务；不等 P3：用 HTTP 上传、准备、执行、取回文件。
- 模拟节点仅用于协议检查，真实设备证据单列。
- 第一份交付：一台真实节点注册，另一台电脑能查询资源、上传再下载同一文件。
- 第二份交付：一种已配置类型真实执行；把地址、类型目录、令牌配置与启动说明交 P2/P4。
- 尽早与 P2 先接一台，再接第二台物理设备，不等所有优化完成。
- 给 P4 提供同一执行器的离线基线命令；输入与 JSONL 输出约定见接口手册，不能让 P4 重写推理代码。

## 7. 完成定义

主责 R01–R12、X01–X02，参与 I01–I08，标准见统一验收表。必须覆盖：竞争最后一槽、接单响应丢失、重复 ID 不同内容、模型未就绪、旧结果、断线、取消与重启恢复。

交付各平台启动说明、锁定配置、实际后端及自测记录、原始执行/事件/采样、模型来源许可。P4 能通过公开接口和授权进程操作复验，不读写你的数据库。
