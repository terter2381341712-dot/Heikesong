# P3：统一前端与用户体验

版本：0.2.0。消费 P1 的资源/文件接口与 P2 的任务接口，不承担业务调度或模型执行。

## 1. 输入与代码边界

计划只编辑 `web/`。读取 [OpenAPI](../contracts/openapi.yaml)、[样例](../contracts/examples.json)、[接口手册](../05-接口契约与联调手册.md)、[类型目录](../contracts/task-types.json)、[验收表](../03-验收与压测.md)。

配置 RESOURCE_BASE_URL、TASK_BASE_URL、DEMO_TOKEN。开发代理将 `/api/resource` 转 P1、`/api/task` 转 P2；生产同源反向代理。地址可配置，不写死某人的局域网 IP。

## 2. 接口连接顺序

| 用户动作 | 调用 | 必须遵守 |
|---|---|---|
| 选择类型 | P2 GET /api/task/v1/task-types | 未配置类型禁用并说明原因 |
| 查看设备 | P1 GET /api/resource/v1/resources | 实际后端、准备状态、占槽、采样 |
| 上传 | P1 POST /api/resource/v1/artifacts | 每文件一个稳定 upload_id，获得 artifact_id |
| 创建任务 | P2 POST /api/task/v1/jobs | 类型、profile/digest、文件 ID、参数、client_request_id |
| 查进度 | P2 GET /api/task/v1/jobs/{id} | 逻辑任务计数、等待/对账/失败原因 |
| 预览 | P2 GET /api/task/v1/jobs/{id}/results | 按 input_index 展示文本/时间段及失败项 |
| 下载 | P2 GET /api/task/v1/jobs/{id}/download | 终态 ZIP，保留失败/取消清单 |
| 取消 | P2 POST /api/task/v1/jobs/{id}/cancel | CANCELLING 不显示成已经全部停止 |
| 节点退出/恢复 | P1 POST /api/resource/v1/resources/{id}/mode | DRAINING 做完当前工作后暂停，ACTIVE 恢复 |

前端永远不持有 TASK_TOKEN、JOIN_TOKEN、节点令牌，不直接下发 execution 绕过 P2。

## 3. 必做交互

- 提交区：类型允许的文件与参数、大小/数量预检、上传进度、Job ID。
- 任务区：逐输入状态、真实节点、尝试、预览、错误、下载、取消。刷新恢复查询，离开页面不取消任务。
- 资源区：检测/手填来源、实际能力、NOT_PREPARED/PREPARING/READY/ERROR、槽位和退出/恢复。
- 连接问题分别标明 P1/P2；旧快照显示已过期，不继续伪造进度。

每 2 秒轮询资源/Job，不堆积请求，切页停止旧轮询。未知指标 N/A，单位按契约，UTC 转北京时间。文件鉴权 fetch/Blob，令牌不进 URL。

上传超时重试原 upload_id；创建超时重试原 client_request_id 和载荷。修改文件/参数后才生成新 ID；重复点击不产生两批 Job。

## 4. 独立开发

先用共享合成样例和 P4 的双服务模拟接口，醒目标记 MOCK；覆盖成功、无资源、准备中、部分失败、连接断开、取消。模拟程序仍待实现，不冒充现成服务。

资源与任务 API 客户端分开封装，切换地址不用重写页面。缺失接口显示未接通，不将样例伪装成真实记录。

## 5. 交付与验收

第一份成果是合成数据的选择类型—上传—提交—预览主路径。之后接真实一机新输入，再展示两机贡献，由 P4 在独立浏览器验收。

主责 U01–U06，参与 I01/I02/I05/I06。通过条件：双服务路由正确、刷新恢复、幂等提交、文件可取、真实状态、生产默认非 MOCK；执行成功与人工质量通过分开。

字段不一致交对应接口负责人/P4处理，不写隐式兼容分支，不自行改 Job 状态、调度或重试。
