# P3：用户网页与设备体验

你的职责是让评委能自己提交新任务、理解设备变化并取回结果。界面上的每个结果和指标都须有服务器数据来源。

## 给 AI 的任务说明

> 实现“弹性商品图工坊”的 React + Vite + TypeScript 前端。先读取 `contracts/openapi.yaml` 和 `contracts/examples.json`。只编辑 `web/`，不要新建自定义后端，不修改 Worker。页面包含提交与成果、设备、事件三个区域。先用明确标注 MOCK 的合成数据开发，再切真实 API。按约定每 2 秒轮询，完成图片多选上传、任务创建、进度、原图/结果预览、结果下载、节点加入指导、正常退出/恢复控制。真实模式不允许用随机数或定时器补造节点和吞吐。

## 必做交互

- 输入服务地址和 DEMO_TOKEN；生产版同源，令牌不拼在 URL。
- 多选 JPG/PNG，前端预检大小，逐张上传后用 input_ids 创建 Job；每次提交生成稳定 client_request_id。
- Job ID 保留在页面地址或本地状态，刷新能重新查询；离开页面不取消服务器任务。
- 显示已成功/失败/运行/排队、可理解的等待原因；不要把“协议执行成功”标成“人工质量通过”。
- 显示原图、透明图棋盘背景、白底图；所有图片用鉴权 fetch Blob；及时回收对象 URL。
- 每张结果显示真实 Worker 名称和处理耗时；失败可见，不静默消失。
- 节点卡显示硬件信息来源、有效 provider、内存、CPU/GPU 读数、已贡献图片数；缺失指标用 N/A。
- 加入设备展示由 P2 最终确认的命令和加入步骤；不要声称网页能扫描所有电脑。
- 退出按钮调用 DRAINING，并解释“完成当前任务后停止”；恢复调用 ACTIVE。
- 真实事件清单显示任务重新分配，不能用动画暗示没有发生的调度。
- 终态下载 ZIP，部分失败时提示包内失败清单。网络断开时显示连接问题，不显示伪造进度。

## 分阶段验收

1. 90 分钟内：用合成样例完成页面主路径，醒目标记 MOCK。
2. 15:00 前：连真实 API，提交新图到两台物理设备并下载。
3. 18:00 前：动态加入、退出、离线、任务重排状态都能理解。
4. 22:00 前：投屏可读、原图结果对照清楚、失败和限制可见。

主要对应 A04/A05/A06/A13/A15；协助 A03/A16。由 P4 在另一个浏览器完成一遍新图操作验收。不要将复杂图表、登录页、聊天框或装饰动画挡在这条流程前面。

## 对接

只访问 P1 的 API；字段差异先报 P1 修改契约或修后端，不写多套隐式兼容分支。P4 提供演示文案与性能报告；正式实测报告的数值直接读取文件/输入已核实数据，标明实验时间，不让 AI 自动生成成绩。
