# P1：协调服务与任务分配

你的职责是让任务、节点和结果状态可信。你同时担任接口负责人，不需要替其他三人完成各自模块。

## 给 AI 的任务说明

> 实现 D 题“弹性商品图工坊”的 Python FastAPI 协调服务。先读取 `contracts/openapi.yaml` 和本执行包的架构、验收文档。只编辑 `server/`、`tests/server/` 和运行时 `contracts/`；不要修改 `worker/`、`web/`、`qa/`、`bench/`。依照接口实现真实行为，不用假节点或预存结果代替功能。先完成上传→建 Job→原子领取→结果提交→下载，再实现心跳租约、正常退出、异常重试和旧尝试拒收。运行单进程服务，SQLite 保存状态，输入结果存在本地。先给出启动命令和一条可用 API 闭环，然后逐步通过验收，不另行引入 Kubernetes、Redis、账号或支付系统。

## 需要实现

- 13 个契约端点与统一错误响应；DEMO/JOIN/Worker 三种令牌角色。
- 图片校验与固定规范化；Asset/Job/Task/Attempt/Worker/Session/Event 数据。
- 注册幂等、新实例使旧会话失效；模型 hash/能力/自测检查。
- 原子 FIFO 领取、一个槽位、领取请求幂等和心跳对账。
- 3 秒心跳、15 秒租约、1 秒扫描、120 秒硬截止、3 次尝试上限、10 秒失败节点冷却。
- DRAINING 完成手头任务后 PAUSED；ACTIVE 恢复。
- complete 校验、临时文件发布、submission 幂等、晚到拒收；ZIP 包含成功结果和失败清单。
- pool 与 job 提供 P3/P4 所需的数据和尝试证据；重启恢复不能丢已完成结果。

## 分阶段交付

| 阶段 | 产物 | 自验 |
|---|---|---|
| 前 90 分钟 | 服务启动、schema、health、上传、建 Job、注册、领取 | 用 HTTP 请求跑通，接口字段与契约一致 |
| 15:00 前 | complete、Job 查询、文件读取、ZIP、真实 Worker 对接 | P2 的两台设备各完成至少一张 |
| 18:00 前 | 动态加入退出、租约、重试、去重 | A04–A14、A17–A18 |
| 22:00 前 | 鉴权、恢复、稳定日志、明确限制 | A16/A19；P4 可运行全链测试 |

## 对接约定

- 向 P2 提供协调服务地址和安全传递的 JOIN_TOKEN；明确模型 SHA 的冻结位置。
- 向 P3 提供 API 地址和 DEMO_TOKEN；不要求前端知道数据库结构。
- 向 P4 提供启动、清空独立测试数据目录的方法；不要公开任意数据修改测试后门。
- 接口修改必须先改运行时契约并写变更说明。所有人确认收到后再切换；当天不做多版本兼容。

## 必须证明的边界案例

两个领取同时到达；领取响应丢失；成功响应丢失；重复 submission 不同内容；任务刚过期收到结果；旧进程在新实例注册后回传；没有 Worker；单图三次失败；服务器重启。用可控单调时间的单元测试验证租约逻辑，不需要测试中实际等待 120 秒。

## 完成定义

P4 能通过公开 API 复现关键路径；两台物理设备的任务结果能追溯；动态退出不丢逻辑任务、不增加重复计数；代码和启动说明可交付。不得仅以“Swagger 页面能打开”验收。
