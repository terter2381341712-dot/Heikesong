# 场景选择与产品定义

## 约束与判断依据

已知设备：M4 MacBook Pro / 16GB；M1 Max MacBook Pro / 64GB；Windows / RTX 4050 Laptop。Windows 的 CPU、系统内存和显存具体数值尚未核实。四位成员都以 AI 辅助开发。有效开发时间约一天。

根据本次已读取的 D 题说明（[来源记录](sources/已读赛题依据.md)），要求至少两台物理设备在同一次测试中完成真实有效计算、统一服务入口、单机与多机正确吞吐对照，以及产品和商业说明。技术 30 分，产品 35 分，资本 35 分。动态加入退出属于我们主动选择的产品能力；自动容错虽非题目强制，但本计划将最小任务重试纳入核心交付，以满足团队明确提出的目标。

以下风险判断是针对这支团队、这些设备和一天赛制的工程判断，不是主办方评分或已测结果。

## 五个候选方案

| 方案 | Demo 实际处理的任务 | 能展示的结果 | 与节点增减的关系 | 一天风险 | 建议 |
|---|---|---|---|---|---|
| **商品素材批处理** | 一批实物照片，逐张抠图、生成白底图和统一尺寸缩略图 | 原图/结果对照、素材逐张出现、ZIP 下载 | 每张图独立，加入立即分担队列，退出只重做未完成图片 | 较低；主要是模型质量和运行环境 | **主推** |
| **采访字幕工厂** | 多段独立采访音频，逐段转录并导出 TXT/SRT | 可播放音频与时间戳字幕 | 按文件分配自然；长音频切块的边界合并需要额外处理 | 中等；解码、识别质量、GPU 依赖、试听时间 | 如果已有真实采访材料，可作为第二选择 |
| **活动素材语义检索** | 活动照片或视频采样帧分布式生成向量，输入文字检索画面 | 输入“舞台上的吉他手”返回相关素材 | 建索引阶段可扩缩，单次文字查询计算较少 | 中高；中文效果、视频抽帧、索引与质量评测增加工作 | 产品吸引力较强，适合有现成积累时选 |
| **商品 360° 渲染农场** | 固定合法模板、可调整颜色和角度，分布式渲染多个帧 | 逐帧完成后合成转台动画 | 帧独立且计算较重，动态节点容易观察 | 高；Blender 安装、场景资产、渲染差异与出片耗时 | 有 Blender 熟练成员或现成场景才推荐 |
| **视频封面与缩略图工厂** | 多个短视频生成固定时间点缩略图、联系表和指定规格封面 | 可浏览的素材联系表 | 每段视频或固定片段独立处理 | 较低到中等；传输可能比计算更重 | 无法完成模型安装时的诚实降级方向 |

推荐商品图的原因：输出几秒到几十秒内就可能逐步可见，具体时间待实测；每个任务输入输出清楚；失联重试不需要恢复复杂模型状态；四个人可按 HTTP 契约同时开发。主要创新叙事落在**小团队按需接入已有设备、提供清楚的贡献与退出体验，并交付可直接使用的素材**。

技术依据：

- [rembg 官方项目](https://github.com/danielgatis/rembg)：支持本地图像背景移除、CPU/NVIDIA GPU 路径及模型会话复用。本方案显式选择本地 `u2net`，不用其云 API 后端。软件许可与模型权重许可需分别记录。
- [ONNX Runtime 执行后端](https://onnxruntime.ai/docs/execution-providers/)：存在 CPU、CUDA、CoreML 等后端，但实际是否生效取决于安装包和模型；本计划不承诺 Mac GPU 加速。
- [faster-whisper 官方项目](https://github.com/SYSTRAN/faster-whisper)：提供 CPU/CUDA 推理和带时间戳的识别输出；未据此推断在我们设备上的速度。
- [OpenCLIP 官方项目](https://github.com/mlfoundations/open_clip)：提供图像和文字编码能力；中文检索质量需单独验证。
- [Blender 命令行渲染](https://docs.blender.org/manual/en/latest/advanced/command_line/render.html)：可后台逐帧渲染；场景和硬件适配仍需验证。

## 推荐产品：弹性商品图工坊

一句话：**把团队暂时空闲的电脑接成一个可随时加入、退出的图片加工队，让一批商品照片自动变成能发布的素材。**

第一批目标用户是假设中的校园文创、社团义卖和小型商品运营团队。P4 今天找 1–2 位相近用户快速了解他们是否有批量图片、目前如何处理、最在意时间还是质量。没有反馈就写“待验证假设”，不能写成已有客户。

价值假设：用户只向一个网页提交；无需给每位使用者单独安装模型；团队在大批量处理时临时贡献设备；设备所有者随时停止接新任务；素材在授权团队网络内流转。这里的“本地”只表示数据不需要交给外部推理服务，**不代表对参与设备所有者不可见**。

与单机工具比较，要用同一批任务的实测总耗时和操作步骤回答优势；与云服务比较，讨论开通、按量使用、团队维护和质量差异，不能预先宣称更便宜。第一阶段更适合可信的小团队共享，不把陌生人的设备市场作为参赛承诺。

## 唯一固定工作负载：`product_image_v1`

输入：JPG/PNG 实物照片，每张不超过 10 MiB、解码后不超过 2000 万像素；每个 Job 1–500 张。网页多选文件逐张上传，不处理上传 ZIP。当天额外设磁盘配额并公开限制。

流水线由 P2 固定并写入 manifest：

1. 协调服务纠正 EXIF 方向，将输入透明区域合成白色，转换 RGB，最长边缩到 1024，保存规范化 PNG。Worker 和单机基线读取完全相同的规范化输入。
2. Worker 使用固定 SHA256 的 `u2net` 权重推理，所有设备模型、阈值和预处理规则一致。
3. 依据前景 mask 的边界框裁剪，等比例放入 1024×1024 画布；主体最长边为画布的 80%，居中，不拉伸。
4. 输出透明 PNG、白底 JPEG（质量 92）和 256×256 WebP 缩略图（质量 85）。如果解码、模型或前景检测失败，返回明确失败原因。
5. 模型会话跨任务复用。每台机器默认一个任务槽位，任务批大小为 1。

每张输入是一项有效任务，三种输出不能算成三项吞吐。UUID、图片名、校验和都能追溯到同一逻辑任务。

主试验使用普通不透明商品，准备少量玻璃、毛绒、重叠物品等困难样本展示局限。空 mask、损坏图不能计为成功；语义质量需要单独检查，不能仅凭文件能打开就称为正确。

`u2net` 是计划默认，尚未在三台机器实测。若开工 90 分钟内存在不可排除的内存或速度问题，统一切换 `u2netp` 并重新验证质量，更新全部 Worker、manifest 和基线。正式比较期间禁止各台机器随意更换模型。若模型依赖无法安装，才考虑上表视频素材方案，并同步修改产品和所有验收标准，不能把简单缩放称为 AI 抠图。

## 范围优先级

| 级别 | 交付内容 |
|---|---|
| P0，必须 | 真正多机计算；配置探测和手工显示信息补充；动态注册；一图一任务；空闲领取；正常退出；失联重排；旧尝试拒收；结果下载；日志；单机/多机证据 |
| P1，P0 稳定后 | 剩余时间估计；更友好的启动命令；CUDA 加速；任务耗时与设备贡献图；1–2 位用户反馈 |
| P2，赛后 | 多任务类型、付费、陌生设备加入、跨公网部署、协调服务高可用、模型切分、多租户、Mac GPU 专项优化 |

其中 Windows GPU 可以优先尝试，但 CPU 路径是环境失败时的合法保底。**动态加入退出不是可删减装饰，它是本团队提出的主线。**

## 成功标准

用户能提交新图片并拿到可用的素材；至少两台物理设备对同一批任务贡献最终结果；第三台加入后能接到真实任务；节点退出不丢掉逻辑任务、不重复累计结果；能解释实测增益与瓶颈。没有设“必须两倍加速”或“聚合效率必须 80%”等未经实测的承诺。
