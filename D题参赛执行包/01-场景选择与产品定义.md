# 产品定义与首版范围

版本：0.2.0。此文件重写旧商品图方案，按团队新决定定义可扩展的多设备任务平台。

## 已确认的用户流程

用户在网页选择一个受支持的任务类型并提交文件；P2 按该类型的固定规则拆成子任务，查询 P1 的资源和能力，选择设备、请求准备并执行；P1 返回单次执行结果；P2按输入顺序汇总，P3展示与下载，P4核验正确性和真实协同。

任务分析指类型、输入、参数校验及预设拆分规则，不要求自然语言 Agent 规划。任务拆分属于 P2，模型和各设备执行属于 P1。

## 首批任务类型：明确且可扩展

| 类型 | 输入边界 | P2 的拆分/汇总 | P1 的单次输出 |
|---|---|---|---|
| ocr.image.v1 | JPG/PNG，每文件≤10 MiB、解码≤2000万像素 | 每图一任务，按输入顺序合并文字，保留每图结果和失败 | OCRResult：全文、文本块、原图坐标、置信度或 null |
| asr.file.v1 | WAV，PCM signed 16-bit、单声道、16000 Hz；0<时长≤60秒，每文件≤2 MiB | 每录音一任务，按文件顺序汇总；各文件时间戳从0开始 | ASRResult：全文、分段起止毫秒、语言和时长 |

一个 Job 仅一种类型，1–200 个输入；同一 Job 重复内容 SHA（上传原字节 SHA）拒绝。不同任务类型分别建 Job。仅 language=auto/zh/en 三种请求参数；具体 profile 须说明所支持语言，不支持时明确拒绝，不能静默换模型。

上表是本版新增的工程契约，不是用户声称已具备的能力或赛事条款。具体模型由 P1 实测选择、记录来源和许可后发布，未配置类型对用户禁用。文件格式由 P1 验证，任务匹配由 P2 验证；前端预检不能代替服务端校验。

## profile 的含义

profile 是一份冻结的执行配置，包括模型权重 SHA、依赖版本范围或锁文件、预处理、后处理、参数和后端支持。P1发布 profile_id 与 profile_digest，P2创建 Job 时锁定二者，每个 execution 原样携带。

digest 是发布的 profile.lock.json **原始文件字节**的 SHA256，P2 当作不透明标识，不重新序列化计算。改动配置必须发布新摘要，不能在运行中让旧 Job 无声切换。

单个发布锁文件符合OpenAPI中的RuntimeProfile，**锁文件本身不含profile_digest**；摘要在生成文件后计算，记录于外部目录及请求，避免把文件自身的hash再写回文件造成循环。共享运行模板只是待填草稿，不能直接作为已发布锁文件。

软件“已安装”、模型“已下载”、节点“在线”和能力“READY”分别记录。只有实际加载、校准成功且匹配当前 profile 的节点可以执行。

## 范围边界

必须：授权设备联网、真实能力、统一资源/执行 API、按类型拆分与汇总、真实多机、幂等和故障边界、前端流程、质量与性能证据。

后续扩展：PDF 按页、长音频按时间段、其他任务类型、更加复杂的调度策略。新增类型需共同定义输入、单次输出、拆分合并、能力准备和验收；不能因为任务名称出现在下拉框就称为支持。

首版不承诺多机切分同一个模型、任意代码执行、自动发现未经授权的电脑、跨公网运营、付费或中心服务高可用。计算节点可增减，资源/任务中心服务须持续运行；中心服务重启恢复单独验收。

## 产品与验证

初始用户假设是有批量识别需求的校园团队或小组；不是已有客户事实。P4收集需求、现有处理方式、等待成本、质量和部署负担；未取得反馈时明确列假设。

成功标准：评委提交新输入，至少两台独立物理设备对同一类任务贡献可追溯结果，能下载有用内容；节点变化有明确反馈，逻辑任务不丢、最终结果不重复；同口径报告正确吞吐与至少一个瓶颈。

质量阈值和实际速度待实测，不预设加速倍数。性能分 OCR 与 ASR 报告，禁止把不同单位相加。详细判定见 [验收与压测](03-验收与压测.md)。
