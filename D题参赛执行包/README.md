# D 题参赛执行包：弹性商品图工坊

编制日期：2026-11-14。截止时间按 **2026-11-15 12:00，Asia/Shanghai** 理解。

**建议选题：给校园文创、社团义卖及小型商品运营团队提供批量图片加工；用随时加入、退出的个人电脑共同完成抠图、白底图和缩略图生成。**

本目录是产品与工程执行计划、接口契约和验收任务，**不是已经实现或实测通过的系统**。性能、三机兼容性、网络条件均待团队验证。四位成员都使用 AI 开发，因此按代码归属分工，不按个人技术背景分工。

## 现场到底做什么

评委提交一批此前没有处理过的商品照片。网页持续出现处理后的素材，并标明由哪台真实电脑完成。处理中，把计算节点从 **2 台变成 3 台，再变成 2 台，再恢复 3 台**，展示任务自动分配、正常退出、断线重试和结果不重复。最后下载完整素材包，展示已完成的单机与多机实测对照。

首批准备 60–120 张不同、获授权的实物照片；试跑后按实际处理速度调整有效素材数量，确保增减节点时还有真实待处理任务。数量是准备建议，不是性能预测。不能复制相同图片或故意加 sleep 来制造工作量。

## 开工顺序

1. 用 20 分钟共同阅读输入输出、API 和验收表，建立一个代码仓库。
2. P1 将契约复制到项目根 `contracts/`；四人的 AI 都以它为准，不各自创造字段。
3. P2 先验证模型和网络；P1、P3、P4同时开始各自任务，前端使用明确标注的 fixture。
4. 先接通一台 Worker，再接第二台，随后验证第三台动态加入和退出。**从第二台开始必须用两台独立物理设备。**
5. 今天 18:00 前争取完成真实动态演示；22:00 后停止增加功能。明天 10:00 冻结代码，11:00 完成交付包。

## 必须共同理解的边界

- 可增减的是**计算 Worker**。M4 上的协调服务固定运行；可以退出 M4 的 Worker，但此时不能关闭协调服务。协调服务高可用、主节点迁移不在一天范围内。
- 支持准备好依赖的授权设备主动接入。用户须先启动 Worker 并输入地址、加入令牌；不会自动扫描或控制陌生电脑。
- 三台机器是本次实测规模。节点数量不写死，但不得宣称已经验证大规模集群。
- 配置决定可用执行后端和资源限额；任务完成速度决定实际领取份额。人工输入的显卡型号不能使不存在的加速能力生效。
- 模型推理在参与设备本地执行。固定流水线只处理图片，不提供任意代码、Shell 或外部付费推理接口。
- 本项目依据本次已读取的 D 赛题；见 [来源记录](sources/已读赛题依据.md)。原 PDF 和压缩包在生成计划后的链接检查时已不在项目目录，未擅自恢复。先前检查的 `campus_gpu_fabric_participant_v2.0.0(2)(1).zip` 包含 **C 题**的规范与冻结 API，不应直接当成 D 的必做清单。
