# P1 资源服务与节点

P1 提供局域网资源目录、文件传输、模型准备与单图执行。当前可运行的 profile 是 `ocr.default.v1`，使用 RapidOCR 和 ONNX Runtime CPU。ASR 在任务目录中显示为 `UNCONFIGURED`。

## 安装和启动

在仓库根目录为 P1 建立独立 Python 环境。当前模型锁要求 Python 3.9.6。P2 使用自己的依赖环境。

```sh
python3.9 -m venv var/venv-p1
var/venv-p1/bin/python -m pip install -r requirements.txt
```

中心机设置三个不同的环境变量 `DEMO_TOKEN`、`TASK_TOKEN`、`JOIN_TOKEN`，然后运行：

```sh
export RESOURCE_BIND_HOST=0.0.0.0
export RESOURCE_PORT=8001
export RESOURCE_DATA_DIR="$PWD/data/resource"
var/venv-p1/bin/python -m resource_service
```

中心服务使用单进程。P2 使用中心机的局域网地址设置 `RESOURCE_BASE_URL`，并设置相同的 `DEMO_TOKEN` 和 `TASK_TOKEN`。用终端环境或进程管理器传入变量，程序启动时只读取环境变量。前台服务和节点用 Ctrl+C 停止。

在每台执行节点设置同一个 `JOIN_TOKEN` 和各自的数据目录，使用中心机真实的局域网 IP：

```sh
export NODE_AGENT_DATA_DIR="$PWD/data/agent"
var/venv-p1/bin/python -m node_agent --server "http://中心机IP:8001" --name "Mac-M1Max"
```

Windows 对应的 Python 路径为 `var\venv-p1\Scripts\python.exe`，PowerShell 用 `$env:变量名` 设置进程环境。实际 Windows 执行仍待设备验收。注册后，已发布的 OCR 能力处于 `NOT_PREPARED` 且 `profile_digest=null`，P2 使用 Job 的摘要发起准备。节点使用仓库中的锁文件，也可通过 `NODE_PROFILES_DIR` 指向同版锁文件目录。节点核对锁文件、模型 SHA、依赖版本、内存、实际后端及自测后才报告 `READY`。更新中心和节点时使用同一版 P1 代码。

## 离线基线 L18

每行 manifest 包含 `input_index`、`input_artifact_id`、`local_path` 和 `input_sha256`。执行时使用与线上相同的锁文件：

```sh
var/venv-p1/bin/python -m node_agent.benchmark \
  --manifest inputs.jsonl --profile profiles/ocr.default.v1.lock.json \
  --backend cpu --threads 2 --output-dir var/baseline --run-id demo
```

标准输出为逐文件记录和一条汇总，实际 provider 与模型 SHA 写入标准错误。退出码 0 表示全部成功，1 表示有输入失败，2 表示配置或启动失败。

## 第二台电脑复验 R01

在第二台电脑上设置 `RESOURCE_BASE_URL` 和 `DEMO_TOKEN`，将 `INPUT` 指向待上传的 PNG。先查询资源，再从同一中心服务下载并比对字节：

```sh
export INPUT=./sample.png
upload_id=$(python3 -c 'import uuid; print(uuid.uuid4())')
api="$RESOURCE_BASE_URL/api/resource/v1"
curl -fsS -H "Authorization: Bearer $DEMO_TOKEN" "$api/resources"
response=$(curl -fsS -H "Authorization: Bearer $DEMO_TOKEN" \
  -F "upload_id=$upload_id" -F "file=@$INPUT;type=image/png" "$api/artifacts")
download_path=$(printf '%s' "$response" | python3 -c 'import json,sys; print(json.load(sys.stdin)["download_path"])')
curl -fsS -H "Authorization: Bearer $DEMO_TOKEN" \
  "$RESOURCE_BASE_URL$download_path" -o downloaded.png
shasum -a 256 "$INPUT" downloaded.png
```

两份 SHA-256 应与上传响应中的 `sha256` 一致。多机 OCR 调度需再检查同一 P2 Job 的执行记录是否包含两台物理节点及各自的输入和结果关联。
