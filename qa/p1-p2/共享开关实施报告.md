# 共享关闭与剩余图片迁移实施报告

2026-11-14。实现基于 wzq@7368ad0 加当前工作区补丁，未提交或推送远程。P1/SOURCE.json 保留导入时 SHA，并另记本轮修改，不再把当前 P1 当成原版快照。

## 改动

- P1 将模型准备及执行放入 spawn 子进程，父进程继续独立心跳。关闭共享后终止子进程，必要时强制 kill，并 join 确认死亡后才发送停止确认。输入下载、模型加载、自测及识别都包含在可终止进程内。每次执行重新加载锁定模型，因此有额外启动开销，保留权重/版本核验，不复用未经核验的模型。
- 本机 `Agent.set_sharing(False)` 先触发本地停止，再同步中心；中心不可达时保持本地关闭并重试。中心通过事务置 PAUSED、禁止新接纳、撤销活动执行提交权，保持清理屏障。重复关闭不会重复清理已确认的工作。
- 心跳续租失败达到保守的 12 秒窗口也会终止子进程，避免失联后持续计算。正常网络下来自中心的关闭最迟随下一次心跳获知（约 3 秒）；本机开关由监督循环约 50ms 检查，加进程终止等待。这里不是零延迟保证。
- 取消确认后保留共享关闭原因，P2 仅将这种 CANCELLED 重新排队；Task ID、输入、profile 不变，旧 execution 历史保留，新派发使用新 ID。成功结果不回退；普通取消和整批 Job 取消维持旧行为。
- 已成功但尚未下载的结果沿原 execution/artifact 取回。共享关闭与成功发布由中心事务确定先后，关闭先发生则拒收迟到结果。
- 准备中关闭变成 FAILED/NODE_UNAVAILABLE；重新开启后 P2 可重新发起准备。清理完成前开启返回 409。接受尝试仍最多 3 次，不能借主动退出重置计数。

## P1 需配合的接口与调用方同步

新增内部接口（仅节点自身凭证，P2 不调用）：

`POST /api/resource/internal/v1/nodes/{worker_id}/sharing`

输入 JSON：`session_id: string(UUID)`、`node_secret: string`、`enabled: boolean`。输出 200：`enabled: boolean`、`mode: ACTIVE|PAUSED`、`cleanup_pending: boolean`。开启时仍有执行/准备或清理屏障返回 409 RESOURCE_BUSY；旧会话/错误秘密凭证返回 409 SESSION_CHANGED；格式错误返回 422。关闭响应仅表示已撤权及停止接单，不能代替实际计算停止确认。

| 现有接口 | 本轮约定与调用方同步 |
|---|---|
| POST `/api/resource/internal/v1/nodes/{worker_id}/heartbeat` | 返回原 `ok/mode/cancel_requested`，新增内部布尔 `sharing_enabled`。Agent 处理取消 ID 及共享标志；缺失该字段按旧中心开启状态处理 |
| POST `/api/resource/internal/v1/nodes/{worker_id}/executions/{execution_id}/cancel_ack` | 输入仍是 session_id/node_secret。只有计算已停止才调用；返回 Execution。共享关闭的终态为 CANCELLED，error.code=NODE_UNAVAILABLE、retryable=true、details.execution_id=原 ID |
| POST `/api/resource/internal/v1/nodes/{worker_id}/confirm_idle` | 输入不变。仅在所有子进程停止、活动执行完成取消确认后清除 cleanup_pending；活动执行存在返回 409 |
| GET `/api/resource/v1/executions/{id}` | 公共 schema 不变；P2 只有确认上述 CANCELLED+错误码+retryable+匹配 execution_id，且 Job 未取消、尝试预算未耗尽时，才转 WAITING_FOR_RESOURCES |
| GET `/api/resource/v1/resources` | 字段不变。关闭表现为 PAUSED、available_slots=0；已准备能力退回 NOT_PREPARED，重新开启后重新准备 |
| POST `/api/task/v1/jobs/{id}/cancel` | 行为不变：取消整批，不迁移。不能用此接口实现设备共享开关 |

公开 OpenAPI 仍为 0.2.0，三份 schema 字节不变；没有添加 Error 枚举。SQLite 自动补 `nodes.sharing_enabled` 列，旧记录默认开启，保留已有数据。建议同时升级中心资源服务、Agent 和 P2：旧 Agent 不会真正中止计算，旧 P2 会把 CANCELLED 当作 Task 终态，不能宣称支持迁移。旧公共 DRAINING/PAUSED 操作仍保留原语义，新增共享关闭走 sharing 接口。

## 使用

保留原 CLI 启动行为以兼容既有部署。选择中心资源服务并使用默认关闭的交互入口：

```sh
cd P1
# 按 P1 README 配置 JOIN_TOKEN、独立 NODE_AGENT_DATA_DIR 等环境变量
.venv/bin/python -m node_agent --server http://中心IP:8001 --name my-device --interactive
```

输入 `on` 才首次注册；输入 `off` 立即触发本机停止并同步中心。再输入 `on` 会等待服务器接受开启；清理未完会重试。中心地址当前仍指资源服务 8001，不能直接填只提供任务 API 的 8002。选择其他中心请先 off，确认停止后退出，用独立节点数据目录启动新中心。桌面安装器、多个中心列表与单地址网关未在本轮实现。
