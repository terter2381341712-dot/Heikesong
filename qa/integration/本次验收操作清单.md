## 5. 吞吐量三组（CPU 单机 / GPU 单机 / 双机）

先决条件：图片、模型、各设备预算固定；**同一批图片**；每组至少三轮，取中位数；通过原工作台开关共享并等服务端确认。

### 现在绝对不要传 `--references`

当前 `P4/var/acceptance-candidates-20261115/references.json` 是 `frozen_before_run=false`、`max_cer=null`。`throughput.py:98-101` 会直接抛「参考文本/阈值未在实验前冻结」并中止。**手册里那三条带 `--references` 的命令现在照抄必失败**。第一轮先不传，工具仍报完成吞吐（张/秒），`reference_status=NOT_RUN`、`formal_benchmark=NOT_RUN` —— 这正好对应用户说的「人工参考后补」。人工核对完、冻结 `frozen_before_run=true` 并填好每张图 SHA 的参考文字后，再重跑带 `--references` 的正式质量/性能轮次。

```sh
P=P2/.venv/bin/python
CFG=P4/var/control/center.json          # 启动中心后才存在
IMG=P4/var/本地验收图片/images
CC=P4/config/compute.cpu-heterogeneous.example.json

$P P4/scripts/throughput.py measure --group cpu  --config $CFG --inputs $IMG --compute-config $CC --rounds 3 --out qa/integration/S2-cpu-20261115
$P P4/scripts/throughput.py measure --group gpu  --config $CFG --inputs $IMG --compute-config $CC --rounds 3 --out qa/integration/S2-gpu-20261115
$P P4/scripts/throughput.py measure --group pool --config $CFG --inputs $IMG --compute-config $CC --devices P4/var/devices.json --rounds 3 --out qa/integration/S2-pool-20261115

$P P4/scripts/throughput.py compare \
  --cpu  qa/integration/S2-cpu-20261115/throughput.json \
  --gpu  qa/integration/S2-gpu-20261115/throughput.json \
  --pool qa/integration/S2-pool-20261115/throughput.json \
  --out  qa/integration/S2-compare-20261115.json
```

- 每个 `--out` 必须是**新目录**，工具用 `mkdir(exist_ok=False)`，重名直接报错。
- `devices.json` 按 `P4/config/devices.example.json` 填两个真实 `worker_id`、不同 `physical_device_id`，`operator_attested` 置 `true`。只有 `--group pool` 强制需要它。
- `--inputs` 目录：只扫直属 `.png/.jpg/.jpeg`，1–200 张，SHA 不可重复。
- 单机组的 `workers` 数量必须为 1，否则工具判 FAIL（所以测 CPU 单机时 B 必须真的关掉共享并被确认）。
- 工具顺序：`initial` → `warmup` → `round-1..3`；失败轮保留、不自动重跑掩盖。
- 确实重启过被测节点才加 `--cold-start-confirmed`；模型加载时间从节点日志单独记，不拿 initial 整个 Job 当加载时间。
- 看：完成吞吐（唯一成功任务数 ÷ Job finished_at−created_at）、三轮中位数、每节点贡献、失败/取消/重复是否误计、双机对最快单机加速比、CPU/RAM/GPU/显存峰值。**0.684 张/秒只是本机候选图完成速率，不能当正式对比结果。**
